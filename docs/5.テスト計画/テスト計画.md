# チャットWebアプリ テスト計画書

## 1. 概要

本資料は、チャットWebアプリMVPのテスト計画をまとめたものである。

本アプリは、外部認証、1対1チャット、リアルタイム更新、画像・ファイル送信を含むため、単純な画面確認だけでなく、認証、権限、DB、Realtime、Storageの連携を確認する必要がある。

---

## 2. 分割資料

テスト計画は、見やすさを優先して以下の3ファイルに分割する。

| ファイル | 内容 |
|---|---|
| `09_test_plan_overview.md` | テスト方針、対象範囲、テスト種別、環境、完了条件 |
| `09_test_cases.md` | 機能別テストケース |
| `09_acceptance_checklist.md` | 受入テスト、リリース前チェックリスト |

---

## 3. テスト目的

MVPとして、以下が正しく動くことを確認する。

- 外部認証でログインできる
- アプリ内ユーザーが作成される
- 未ログインユーザーは保護画面にアクセスできない
- 自分以外のユーザー一覧を表示できる
- 1対1チャットルームを作成できる
- 既存の1対1チャットルームを再利用できる
- メッセージを送信できる
- メッセージ一覧を表示できる
- 相手画面にリアルタイムで反映される
- 画像を送信できる
- ファイルを送信できる
- 自分が参加していないルームにはアクセスできない
- Vercel上でMVP機能が動作する

---

## 4. テスト対象

## 4.1 対象機能

| 分類 | 対象 |
|---|---|
| 認証 | ログイン、ログアウト、認証ガード |
| ユーザー | アプリ内ユーザー作成、ユーザー一覧 |
| チャットルーム | 作成、一覧、既存ルーム再利用、参加者チェック |
| メッセージ | 一覧取得、テキスト送信、バリデーション |
| Realtime | 新着メッセージのリアルタイム反映 |
| ファイル | 画像送信、ファイル送信、サイズ/形式チェック |
| UI | ローディング、エラー、空状態 |
| デプロイ | Vercel環境での動作 |

---

MVPでは以下はテスト対象外とする。

- 管理者機能
- スマホ最適化
- グループチャット
- 既読機能
- 未読数表示
- プッシュ通知
- メッセージ検索
- メッセージ編集
- メッセージ削除
- 通報機能
- ブロック機能
- タイピング中表示
- オンライン状態表示
- 音声通話
- ビデオ通話

## 5. テスト種別

## 5.1 単体テスト

### 目的

関数単位で正しく動くことを確認する。

### 対象

- `validateTextMessage`
- `validateFile`
- `sanitizeFileName`
- `formatFileSize`
- `successResponse`
- `errorResponse`
- `createStoragePath`

### ツール候補

- Vitest

---

## 5.2 コンポーネントテスト

### 目的

UIコンポーネントが期待通りに表示・操作できることを確認する。

### 対象

- MessageBubble
- MessageInput
- ImageMessage
- FileMessage
- ErrorMessage
- EmptyState
- ChatRoomListItem
- UserListItem

### ツール候補

- React Testing Library
- Vitest

---

## 5.3 APIテスト

### 目的

APIが認証、権限、バリデーション、DB操作を正しく処理することを確認する。

### 対象

- `GET /api/me`
- `GET /api/users`
- `GET /api/chat-rooms`
- `POST /api/chat-rooms/direct`
- `GET /api/chat-rooms/:roomId`
- `GET /api/chat-rooms/:roomId/messages`
- `POST /api/chat-rooms/:roomId/messages`
- `POST /api/files/validate`
- `POST /api/chat-rooms/:roomId/attachments`

### 方法

MVPでは最初は手動確認を中心にする。  
余裕があればAPI単体テストまたはE2Eで補完する。

---

## 5.4 結合テスト

### 目的

画面、API、DB、Storage、Realtimeが連携して正しく動くことを確認する。

### 主な確認

- ログイン後にusersが作成される
- ユーザー一覧からチャットルームを作れる
- ルーム一覧からチャット画面へ遷移できる
- メッセージ送信後にDBに保存される
- 相手画面にRealtimeで反映される
- Storageへアップロード後、DBに添付情報が保存される

---

## 5.5 E2Eテスト

### 目的

ユーザー操作に近い形で、主要導線が正常に動くことを確認する。

### 対象シナリオ

- ログイン
- チャット相手選択
- メッセージ送信
- 画像送信
- ファイル送信
- ログアウト

### ツール候補

- Playwright

MVP初期では手動テストで代替し、MVP完成後にPlaywright導入を検討する。

---

## 5.6 受入テスト

### 目的

MVPとして利用できる状態かを最終確認する。

### 対象

- 2ユーザーでの1対1チャット
- Realtime反映
- 画像・ファイル送信
- 権限チェック
- Vercelデプロイ環境での確認

```md

### 発生環境

### 期待結果

### 実際の結果

### 原因

### 対応方針

```

---

## 9.2 優先度

| 優先度 | 内容 |
|---|---|
| Critical | ログイン不可、チャット不可、データ漏洩などMVP継続不能 |
| High | 主要機能が使えない |
| Medium | 一部機能に問題があるが回避可能 |
| Low | 表示崩れ、軽微な文言ミス |

---

## 10. テスト完了条件

MVPのテスト完了条件は以下。

```text
・Critical / High の不具合が0件
・認証、チャット、メッセージ、Realtime、ファイル送信が動作する
・未ログインアクセス制限が動作する
・他人のルームにアクセスできない
・Vercel環境で主要導線が動作する
・READMEの手順で起動できる
・テスト結果が記録されている
```

## 11. 自動テスト導入方針

MVPでは、まず手動テストを重視する。  
ただし、以下は自動テスト化しやすいため、早めに導入してもよい。

| 対象 | 優先度 |
|---|---|
| validateTextMessage | 高 |
| validateFile | 高 |
| sanitizeFileName | 高 |
| formatFileSize | 中 |
| MessageInput | 中 |
| MessageBubble | 中 |

E2EはMVP完成後にPlaywrightで導入する。
