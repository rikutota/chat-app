## 9. `/api/me` 詳細設計

## 9.1 目的

ログイン中ユーザーのアプリ内ユーザー情報を取得する。  
初回ログイン時は `users` テーブルにレコードを作成する。

---

## 9.2 処理フロー

```text
1. Supabase Authセッション取得
2. セッションがなければ401
3. auth_user_idを取得
4. users.auth_user_idで検索
5. usersが存在する場合
   5-1. ユーザー情報を返す
6. usersが存在しない場合
   6-1. auth user metadataから表示名を取得
   6-2. emailを取得
   6-3. avatar_urlを取得
   6-4. usersへINSERT
   6-5. 作成したユーザー情報を返す
```

---

## 9.3 表示名決定ルール

優先順位:

```text
1. user_metadata.full_name
2. user_metadata.name
3. emailの@より前
4. 'user'
```

---

## 9.4 疑似コード

```ts
async function getOrCreateCurrentAppUser() {
  const supabase = createServerSupabaseClient();

  const {
    data: { user: authUser },
    error: authError,
  } = await supabase.auth.getUser();

  if (authError || !authUser) {
    throw new ApiError('UNAUTHORIZED', 'ログインしてください', 401);
  }

  const { data: existingUser } = await supabase
    .from('users')
    .select('*')
    .eq('auth_user_id', authUser.id)
    .single();

  if (existingUser) {
    return existingUser;
  }

  const displayName =
    authUser.user_metadata?.full_name ??
    authUser.user_metadata?.name ??
    authUser.email?.split('@')[0] ??
    'user';

  const avatarUrl = authUser.user_metadata?.avatar_url ?? null;

  const { data: createdUser, error } = await supabase
    .from('users')
    .insert({
      auth_user_id: authUser.id,
      display_name: displayName,
      avatar_url: avatarUrl,
      email: authUser.email ?? null,
    })
    .select('*')
    .single();

  if (error) {
    throw new ApiError('INTERNAL_ERROR', 'ユーザー情報の作成に失敗しました', 500);
  }

  return createdUser;
}
```

## 12. 1対1チャットルーム作成詳細

## 12.1 対象API

```text
POST /api/chat-rooms/direct
```

---

## 12.2 目的

指定した相手ユーザーとの1対1チャットルームを作成する。  
既に存在する場合は、既存ルームを返す。

---

## 12.3 入力

```json
{
  "partnerUserId": "partner-user-uuid"
}
```

---

## 12.4 バリデーション

| 項目 | ルール |
|---|---|
| partnerUserId | 必須 |
| partnerUserId | UUID形式 |
| partnerUserId | usersに存在する |
| partnerUserId | 自分自身ではない |

---

## 12.5 処理フロー

```text
1. getCurrentAppUserで自分を取得
2. request bodyからpartnerUserIdを取得
3. partnerUserIdを検証
4. partnerUserIdのusers存在確認
5. partnerUserIdが自分自身なら400
6. 自分が参加しているroom_id一覧を取得
7. そのroom_id一覧の中でpartnerUserIdも参加しているroomを探す
8. 見つかった場合
   8-1. 既存roomを返す
9. 見つからない場合
   9-1. direct_chat_roomsへINSERT
   9-2. direct_chat_room_membersへ自分をINSERT
   9-3. direct_chat_room_membersへ相手をINSERT
   9-4. 作成したroomを返す
```

---

## 12.6 疑似コード

```ts
async function findOrCreateDirectRoom(currentUserId: string, partnerUserId: string) {
  if (currentUserId === partnerUserId) {
    throw new ApiError('VALIDATION_ERROR', '自分自身とはチャットできません', 400);
  }

  const partner = await findUserById(partnerUserId);

  if (!partner) {
    throw new ApiError('NOT_FOUND', 'ユーザーが見つかりません', 404);
  }

  const myRooms = await getRoomIdsByUserId(currentUserId);

  const existingRoom = await findRoomIncludingUsers(myRooms, [
    currentUserId,
    partnerUserId,
  ]);

  if (existingRoom) {
    return {
      room: existingRoom,
      partner,
      isNew: false,
    };
  }

  const room = await createDirectChatRoom();

  await insertRoomMembers(room.id, [currentUserId, partnerUserId]);

  return {
    room,
    partner,
    isNew: true,
  };
}
```

## 12.7 注意点

MVPではアプリ側で重複確認するため、完全な同時実行対策は弱い。

例:

```text
User AがUser Bとのルーム作成を連続で実行
  ↓
同時に既存チェックが走る
  ↓
両方とも「存在しない」と判断
  ↓
重複ルームができる可能性
```

将来的には `room_key` を導入し、DBのUNIQUE制約で防ぐ。

## 15.4 疑似コード

```ts
async function assertRoomMember(roomId: string, userId: string) {
  const { data, error } = await supabase
    .from('direct_chat_room_members')
    .select('id')
    .eq('room_id', roomId)
    .eq('user_id', userId)
    .maybeSingle();

  if (error) {
    throw new ApiError('INTERNAL_ERROR', '参加者情報の確認に失敗しました', 500);
  }

  if (!data) {
    throw new ApiError('ROOM_ACCESS_DENIED', 'このチャットにはアクセスできません', 403);
  }
}
```

## 17.5 疑似コード

```ts
async function sendTextMessage(roomId: string, body: string) {
  const appUser = await getCurrentAppUser();

  await assertRoomExists(roomId);
  await assertRoomMember(roomId, appUser.id);

  validateTextMessage(body);

  const { data, error } = await supabase
    .from('messages')
    .insert({
      room_id: roomId,
      sender_id: appUser.id,
      message_type: 'text',
      body: body.trim(),
    })
    .select('*')
    .single();

  if (error) {
    throw new ApiError('INTERNAL_ERROR', 'メッセージの送信に失敗しました', 500);
  }

  return data;
}
```

## 18.5 疑似コード

```ts
function validateFile(input: FileValidationInput) {
  if (!input.fileName || !input.mimeType || !input.fileSize || !input.fileKind) {
    throw new ApiError('VALIDATION_ERROR', 'ファイル情報が不正です', 400);
  }

  if (input.fileKind === 'image') {
    if (input.fileSize > 5 * 1024 * 1024) {
      throw new ApiError('FILE_TOO_LARGE', '画像サイズは5MB以内にしてください', 413);
    }

    if (!ALLOWED_IMAGE_MIME_TYPES.includes(input.mimeType)) {
      throw new ApiError('FILE_TYPE_NOT_ALLOWED', 'この画像形式は送信できません', 415);
    }
  }

  if (input.fileKind === 'file') {
    if (input.fileSize > 10 * 1024 * 1024) {
      throw new ApiError('FILE_TOO_LARGE', 'ファイルサイズは10MB以内にしてください', 413);
    }

    if (!ALLOWED_FILE_MIME_TYPES.includes(input.mimeType)) {
      throw new ApiError('FILE_TYPE_NOT_ALLOWED', 'このファイル形式は送信できません', 415);
    }
  }
}
```

```ts
function createStoragePath(roomId: string, fileName: string) {
```

## 21.3 処理フロー

## 21.4 疑似コード

```ts
useEffect(() => {
  const supabase = createBrowserSupabaseClient();

  const channel = supabase
    .channel(`room-${roomId}`)
    .on(
      'postgres_changes',
      {
        event: 'INSERT',
        schema: 'public',
        table: 'messages',
        filter: `room_id=eq.${roomId}`,
      },
      async (payload) => {
        const messageId = payload.new.id;

        if (messages.some((message) => message.id === messageId)) {
          return;
        }

        const message = await fetchMessageDetail(messageId);
        setMessages((prev) => [...prev, message]);
      }
    )
    .subscribe();

  return () => {
    supabase.removeChannel(channel);
  };
}, [roomId]);
```

## 24. バリデーション詳細

## 24.1 メッセージ本文

```ts
const MAX_MESSAGE_LENGTH = 2000;

function validateTextMessage(body: unknown): string {
  if (typeof body !== 'string') {
    throw new ApiError('MESSAGE_EMPTY', 'メッセージを入力してください', 400);
  }

  const trimmed = body.trim();

  if (!trimmed) {
    throw new ApiError('MESSAGE_EMPTY', 'メッセージを入力してください', 400);
  }

  if (trimmed.length > MAX_MESSAGE_LENGTH) {
    throw new ApiError(
      'MESSAGE_TOO_LONG',
      'メッセージは2000文字以内で入力してください',
      400
    );
  }

  return trimmed;
}
```

```ts
function sanitizeFileName(fileName: string): string {
```

## 25. セキュリティ詳細

## 25.1 APIで必ずチェックすること

| 項目 | 理由 |
|---|---|

## 25.3 XSS対策

メッセージ本文はHTMLとして描画しない。  
Reactの通常の文字列描画を利用する。

禁止:


推奨:

```tsx
<p>{message.body}</p>
```

## 27. トランザクション設計

## 27.1 課題

Supabase Clientから複数テーブルを順に操作すると、途中失敗時に不整合が起きる可能性がある。

対象:

- ルーム作成 + メンバー2件作成
- メッセージ作成 + 添付作成

---

## 27.2 MVPでの方針

MVPでは実装の分かりやすさを優先し、API内で順次処理する。

ただし、失敗時はできる範囲で補正する。

例:

```text
room作成成功
member登録失敗
  ↓
作成済みroomを削除する
```

## 27.3 将来的な改善

## 28. RLS詳細方針

MVPの初期実装では、まずAPI側チェックを完成させる。

- 自分以外のsender_idでmessagesを作れないようにする
