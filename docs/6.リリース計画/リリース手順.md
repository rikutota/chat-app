# チャットWebアプリ リリース手順書

## 1. 概要

本資料は、チャットWebアプリMVPをVercelへデプロイする具体的な手順をまとめたものである。

---

## 2. 事前準備

### 必要なアカウント

- GitHub
- Vercel
- Supabase
- Google Cloud Console

### 必要な情報

| 項目 | 内容 |
|---|---|
| Supabase Project URL | `NEXT_PUBLIC_SUPABASE_URL` に設定 |
| Supabase Anon Key | `NEXT_PUBLIC_SUPABASE_ANON_KEY` に設定 |
| Vercel Production URL | Supabase Auth Redirect URLに設定 |
| Google OAuth Client ID | Supabase Authに設定 |
| Google OAuth Client Secret | Supabase Authに設定 |

---

## 3. Supabase設定

## 3.1 Supabaseプロジェクト作成

```text
1. Supabaseにログイン
2. New projectを作成
3. Project nameを設定
4. Database passwordを設定
5. Regionを選択
6. 作成完了を待つ
```

---

## 3.2 環境変数取得

Supabase Dashboardから以下を取得する。

```text
Project Settings
  ↓
API
  ↓
Project URL
anon public key
```

`.env.local` に設定する。

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
```

---

## 3.3 DBテーブル作成

Supabase SQL Editorで、`04_database_design.md` のSQLを実行する。

作成対象:

- users
- direct_chat_rooms
- direct_chat_room_members
- messages
- message_attachments
- index
- updated_at trigger

確認:

```text
Table Editorで各テーブルが表示されること
```

---

## 3.4 Supabase Auth設定

Google OAuthを設定する。

```text
1. Supabase Dashboardを開く
2. Authentication > Providers
3. Googleを有効化
4. Client IDを設定
5. Client Secretを設定
6. 保存
```

---

## 3.5 Redirect URL設定

Supabase AuthのURL設定に以下を追加する。

### ローカル

```text
http://localhost:3000/**
```

### Vercel Preview

```text
https://*.vercel.app/**
```

### Vercel Production

```text
https://your-production-domain.vercel.app/**
```

独自ドメインを使う場合:

```text
https://your-domain.com/**
```

---

## 3.6 Google Cloud Console設定

Google OAuth側にもリダイレクトURLを設定する。

Supabaseが提示するCallback URLをGoogle Cloud Consoleに登録する。

例:

```text
https://xxxx.supabase.co/auth/v1/callback
```

注意:

- Vercel URLをGoogle Cloud Consoleに直接入れるのではなく、Google OAuthのCallbackは基本的にSupabaseのCallback URLを使う
- Vercel URLはSupabase Auth側のRedirect URLに追加する

---

## 3.7 Supabase Storage設定

### バケット作成

```text
1. Supabase Dashboard
2. Storage
3. New bucket
4. bucket name: chat-attachments
5. Public / Private を選択
```

MVPでは実装しやすさを優先し、Publicで検証してもよい。  
ただし、本格的な本番公開ではPrivate + Signed URLを検討する。

---

## 3.8 Supabase Realtime設定

Supabaseで `messages` テーブルのRealtimeが有効になっていることを確認する。

確認項目:

```text
・messages INSERTが購読できる
・room_idでfilterできる
・チャット画面で新着が表示される
```

## 5. Vercel設定

## 5.1 Vercelプロジェクト作成

```text
1. Vercelにログイン
2. Add New Project
3. GitHubリポジトリを選択
4. Framework Preset: Next.js
5. Build Commandを確認
6. Output Directoryを確認
7. Environment Variablesを設定

```

---

## 5.2 Vercel環境変数

Vercel Project Settings > Environment Variables に以下を設定する。

```env
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_ANON_KEY=
```

設定対象:

- Production
- Preview
- Development

## 5.3 Build設定

通常はNext.jsのデフォルトでよい。

| 項目 | 値 |
|---|---|
| Framework | Next.js |
| Build Command | `next build` |
| Install Command | `pnpm install` または `npm install` |
| Output Directory | `.next` |

pnpmを使う場合は `pnpm-lock.yaml` をコミットする。

## 7. 本番動作確認手順

## 7.1 トップ画面

```text
1. Vercel Production URLを開く
2. トップ画面が表示されること
3. ログイン導線が表示されること
```

## 7.2 ログイン

```text
1. ログイン画面を開く
2. Googleログインを実行
3. `/chats` へ遷移すること
4. Supabase usersテーブルにレコードがあること
```

## 7.3 チャット作成

```text
1. User Aでログイン
2. User Bを別ブラウザまたは別アカウントで用意
3. User Aで `/users` を開く
4. User Bを選択
5. チャットルームが作成されること
```

## 7.4 メッセージ送信

```text
1. User AとUser Bで同じroomを開く
2. User Aがメッセージ送信
3. User A画面に表示されること
4. User B画面にもRealtimeで表示されること
```

## 7.5 画像・ファイル送信

```text
1. User Aが画像を送信
2. User B画面に画像が表示される
3. User AがPDFなどのファイルを送信
4. User B画面にファイル名とサイズが表示される
5. ファイルを開けるまたは取得できる
```

## 7.6 権限確認

```text
1. User AとUser Bでroomを作成
2. User Cでログイン
3. User CがA/Bのroom URLを直接開く
4. アクセス拒否になること
```

## 8. よくあるリリース失敗と対処

## 8.1 Vercel build失敗

原因候補:

- TypeScriptエラー
- 環境変数不足
- package lock不整合
- import pathミス

対処:

```text
・ローカルで `pnpm build` を実行
・Vercelログを確認
・環境変数を確認
・lockfileを確認
```

## 8.2 Googleログイン後に戻ってこない

原因候補:

- Supabase Redirect URL不足
- OAuth callback設定ミス
- redirectToのURLミス

対処:

```text
・Supabase Auth URL設定を確認
・Google Cloud ConsoleのCallback URLを確認
・Vercel Production URLを追加
```

## 8.3 Supabaseに接続できない

原因候補:

- `NEXT_PUBLIC_SUPABASE_URL` のミス
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` のミス
- Vercel環境変数の設定対象がProductionに入っていない

対処:

```text
・Vercel Environment Variablesを確認
・Productionに設定されているか確認
・再デプロイする
```

## 8.4 Realtimeが動かない

原因候補:

- messagesテーブルのRealtimeが有効でない
- 購読filterが間違っている
- room_idの値が一致していない
- RLSでselectできていない

対処:

```text
・messagesのINSERTを手動で確認
・room_id filterを確認
・Supabase Realtime設定を確認
・RLSを一時的に見直す
```

## 8.5 ファイルアップロードできない

原因候補:

- Storage bucketがない
- Storage policyが不足
- filePathが不正
- ファイルサイズ制限
- MIMEタイプ制限

対処:

```text
・chat-attachments bucketを確認
・Storage policyを確認
・ブラウザconsoleを確認
・APIのvalidate結果を確認
```
