# チャットWebアプリ 基本設計書

## 1. 概要

本資料は、チャットWebアプリの基本設計をまとめたものである。

本アプリは、外部認証を利用し、ユーザー同士が1対1でリアルタイムにメッセージを送受信できるWebアプリである。  
画像・ファイル送信にも対応する。

本設計では、学習用構成として以下の技術を前提にする。

| 分類 | 技術 |
|---|---|
| フロントエンド | Next.js |
| 言語 | TypeScript |
| UI | Tailwind CSS |
| 認証 | Supabase Auth |
| DB | Supabase PostgreSQL |
| リアルタイム通信 | Supabase Realtime |
| ファイル保存 | Supabase Storage |
| ホスティング | Vercel |

---

### 操作

| 操作 | 内容 |
|---|---|
| チャット開始 | 既存1対1ルームを確認し、なければ作成する |

---

## 6.5 S05 チャット画面

### 目的

1対1チャットを行う。

### 表示項目

- チャット相手名
- メッセージ一覧
- テキスト入力欄
- 画像添付ボタン
- ファイル添付ボタン
- 送信ボタン
- 送信中表示
- エラー表示

### 操作

| 操作 | 内容 |
|---|---|
| テキスト入力 | 送信内容を入力 |
| 送信ボタン押下 | メッセージを送信 |
| 画像選択 | 画像をアップロードし、画像メッセージとして送信 |
| ファイル選択 | ファイルをアップロードし、ファイルメッセージとして送信 |
| 戻る | チャットルーム一覧へ戻る |

### リアルタイム処理

- チャット画面表示時に対象ルームのメッセージ購読を開始する
- 新しいメッセージがDBに追加されたら画面に反映する
- 画面離脱時に購読を解除する

## 10. リアルタイム設計概要

## 10.1 基本方針

メッセージ送信時は、まずDBにメッセージを保存する。  
その後、Supabase Realtimeの購読により、同じチャットルームを開いているユーザーの画面に新着メッセージが反映される。

---

## 10.2 処理イメージ

```text
送信者
  ↓
メッセージ送信
  ↓
messages テーブルへINSERT
  ↓
Supabase RealtimeがINSERTを検知
  ↓
受信者の画面に新着メッセージ表示
```

---

## 10.3 購読単位

チャット画面を開いたとき、対象の `room_id` に紐づく `messages` の追加を購読する。

```text
messages.room_id = 現在開いているroomId
```

---

## 10.4 購読解除

チャット画面から離脱したとき、Realtimeの購読を解除する。

---

## 11. ファイル送信設計概要

## 11.1 基本方針

画像やファイルはDBに直接保存しない。  
Supabase Storageに保存し、DBにはファイル情報とStorage上のパスを保存する。

---

## 11.2 処理イメージ

```text
ファイル選択
  ↓
ファイルサイズ・形式チェック
  ↓
Supabase Storageへアップロード
  ↓
messages テーブルへメッセージ作成
  ↓
message_attachments テーブルへ添付情報作成
  ↓
Realtimeで相手画面に反映
```

---

## 11.3 画像とファイルの扱い

| 種別 | 表示 |
|---|---|
| 画像 | チャット画面内でプレビュー表示 |
| ファイル | ファイル名、サイズ、ダウンロードリンクを表示 |

---

## 11.4 初期制限

| 項目 | 制限 |
|---|---|
| 画像形式 | jpg, jpeg, png, webp |
| ファイル形式 | pdf, txt, csv, zip など。詳細はDB/API設計時に決定 |
| ファイルサイズ | 技術検証後に決定 |
| 複数ファイル同時送信 | 初期開発では対象外 |

## 12. エラー設計概要

## 12.1 共通エラー

| エラー | 表示例 |
|---|---|
| 未ログイン | ログインしてください |
| 権限なし | このチャットにはアクセスできません |
| メッセージ未入力 | メッセージを入力してください |
| ファイルサイズ超過 | ファイルサイズが大きすぎます |
| ファイル形式不正 | このファイル形式は送信できません |
| アップロード失敗 | ファイルのアップロードに失敗しました |
| 送信失敗 | メッセージの送信に失敗しました |
| 通信エラー | 通信に失敗しました。時間をおいて再試行してください |

---

## 12.2 エラー表示方針

- ユーザーに分かる言葉で表示する
- 技術的な詳細をそのまま表示しない
- 開発中はconsoleやログで詳細確認できるようにする
- 本番公開時にはSentryなどのエラー監視を検討する

## 14. セキュリティ設計概要

MVPでも以下は実装対象とする。

- 認証が必要な画面へのアクセス制限
- 認証が必要なDB操作の制限
- 自分が参加していないチャットルームへのアクセス禁止
- 自分が参加していないチャットルームへのメッセージ送信禁止
- ファイル形式制限
- ファイルサイズ制限
- HTMLエスケープ
- `.env.local` をGit管理しない
- Supabase RLSの検討

本番公開前に追加検討するもの。

- レート制限
- 通報機能
- ブロック機能
- 不適切ファイル対策
- ウイルススキャン
- 利用規約
- プライバシーポリシー
- エラー監視
- 監査ログ

---

## 15. ログ設計概要

MVPでは詳細なログ基盤は作らないが、以下は確認できる状態にする。

- ログイン成功 / 失敗
- メッセージ送信失敗
- ファイルアップロード失敗
- 認証エラー
- 権限エラー
- Realtime接続エラー

本番公開前には、Sentryなどのエラー監視サービス導入を検討する。
